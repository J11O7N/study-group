# study-group
# 오픈 미션 - 스터디그룹

---
## 🎯 목표
프리코스에서 제가 가장 인상 깊게 느꼈던 경험은 스터디에 참여했던 순간들이었습니다.
그때의 기억들은 함께 성장하고 배우며 느꼈던 성취감과 즐거움으로 오래 남았습니다.
그래서 이 경험을 직접 하나의 스토리로 풀어내고, 제가 배운 프로그래밍 기술로 재구성해 보고자 했습니다.
그 결과, 스터디 운영의 전 과정을 하나의 흐름으로 표현한 ‘스터디그룹’ 오픈미션을 만들게 되었습니다.
이 프로젝트는 프리코스에서 배운 불변성, 일급컬렉션, Enum 기반 정책, 의존성 주입(DI), 테스트 등 가능한 설계 원칙을 토대로, 저의 스터디 경험을 프로그래밍적으로 구조화하고 시뮬레이션한 결과물입니다.
---
## 기능 목록
### 1. 입력

| 항목        | 설명                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------ |
| 팀장 정보 입력  | 이름, 분야, 가능 지역, 가능한 요일·시간, 선정 키워드 3개                                                              |
| 지원자 정보 입력 | 이름은 `com.github.javafaker.Faker(ko)`로 랜덤, 분야/사는 지역/가능 시간은 프로젝트 내 직접 정의 리스트에서 랜덤 선택 + 지원동기(랜덤 문장) |
| 입력 형식     | CLI 입력 / JSON 파일 확장 가능 (동일 스키마)                                                                  |
| 검증 로직     | 공백, 중복 이름 허용(시뮬), 유효하지 않은 시간대/없는 지역/없는 분야 차단, 키워드 최소 1개 이상                                       |

---

### 2. 필터링 및 선발

| 항목        | 설명                                     |
| --------- | -------------------------------------- |
| 분야/지역 필터링 | (선택) 리더 기준으로 사전 필터링 가능. 단, 필수는 아님      |
| 시간 필터링    | `TimeMask`(7×24 비트마스크) 기반 교집합 도출(참여 가능 확인용) |
| 선정 정책(최종) | 팀장이 지정한 키워드가 지원동기에 1개 이상 포함된 지원자만 최종 후보 |
| 정원/타이브레이커 | 정원 초과 시 선착순(등록 순서) 로 컷. (옵션: 고정 시드 랜덤) |
| 최대 인원     | 팀장 포함 최대 5명(설정값으로 변경 가능)               |

---

### 3. 시간 조율

| 항목       | 설명                                          |
| -------- | ------------------------------------------- |
| 시간 표현 방식 | `TimeMask` 클래스로 요일·시간을 비트 단위 표현 (7일 × 24시간) |
| 공통 가능 시간 | 리더 + 선발된 후보들의 `AND` 연산으로 교집합 시간 자동 산출       |
| 우선순위     | 교집합이 여러 개인 경우: “참여 인원 최댓값 → 리더 선호 요일” 순     |
| 예외 처리    | 공통 시간이 없으면 가까운 시간대(해밍거리 최소) 자동 추천           |

---

### 4. 장소 추천

| 항목    | 설명                                     |
| ----- | -------------------------------------- |
| 위치 입력 | 각 지원자의 직접 정의 지역(예: “강남”, “홍대”, “판교” 등) |
| 거리 계산 | (간단) 사전 정의된 거리 테이블 또는 카테고리 매칭 점수       |
| 후보 장소 | 직접 정의된 스터디카페 리스트 사용 (API 미사용 버전)       |
| 최종 결정 | 중심/다수결 기준으로 하나 선택 (가장 가까운/가장 빈도 높은 후보) |

---

### 5. 대화 출력

| 항목    | 설명                                      |
| ----- | --------------------------------------- |
| 리더 대사 | “이번 주 금요일 20시에 강남 스터디카페 A로 진행해도 될까요?”   |
| 팀원 응답 | “예 / 조금 늦습니다 / 불가능합니다” 등 시뮬레이션 응답       |
| 대화 흐름 | Leader → Members → Leader (확정/리마인드)     |
| 출력 포맷 | CLI 콘솔, `Conversation`/`Message` 모델로 관리 |

---

### 6. 결과 요약

| 항목       | 설명                                      |
| -------- | --------------------------------------- |
| 최종 매칭 결과 | 키워드 매칭으로 선발된 인원 목록, 공통 시간, 장소, 리더 최종 멘트 |
| 형식       | 표/텍스트/JSON 중 선택 출력                      |
| 저장       | (선택) `ResultExporter`로 CSV/TXT 저장       |

## 파일 구조

```text
studymatch/
├── Application.java                    
│
├── controller/
│   └── StudyGroupController.java         # 흐름 제어
│
├── service/
│   └── StudyGroupService.java            # 비즈 로직 오케스트레이션
│
├── domain/
│   ├── person/
│   │   ├── Applicant.java                
│   │   └── Leader.java                   
│   │
│   ├── time/
│   │   └── TimeMask.java                 # 7×24 비트마스크, 교집합 연산

├── support/
│   └── generator/

│
├── view/
│   ├── InputView.java                    # 입력
│   └── OutputView.java                   # 출력
│
└── util/
```
